# 云间共读

邀请制的善友共学空间。首版面向管理员直接认识的成年成员：**一人领读，其他人自愿参与**。

这不是宗教认证、修为评价或金融平台。「庭院」「愿力」「功德币」是产品内的体验与制度用语，不声称重现超自然天界。

## 1. 本机启动

需要 Node.js **24 或更新版本**。推荐先安装当前维护中的 Node 24 LTS。

最省事的方式：在本目录双击 **`启动庭院.cmd`**。它会检查依赖、构建网页并在终端启动服务；首次建站码显示在该窗口里。然后用浏览器打开下方地址。

也可以在本目录打开终端：

```bash
npm install
npm run build
npm start
```

打开：**http://127.0.0.1:4317**

第一次启动，终端会显示随机的「首次建站码」。在网页输入建站码，自己设置管理员称呼、邮箱和至少 12 字符的密码。没有默认管理员密码，也没有预置真实成员。

- 建站码只用于创建第一个管理员，不是邀请链接，不要发给成员。
- 管理员建立后，重启不会清空账号、笔记、余额或共同成果。
- 程序默认只监听本机，**不会发布到公网**。
- 关闭终端中的服务可按 `Ctrl+C`；再次运行 `npm start` 即可回来。
- `.env.example` 是配置说明，程序**不自动加载 `.env`**。请设置系统环境变量；也可以自行使用 Node 的 `--env-file` 启动选项。

开发模式：

```bash
npm run dev
```

开发网页为 http://127.0.0.1:5179，API 为 http://127.0.0.1:4317。两者通过 Vite 代理连接。开发端口固定，不会自动漂移。

### Windows 构建兼容

本机 Node 24 / Windows 在重复构建时，进程会在清理旧输出目录阶段异常退出。项目设置 `build.emptyOutDir=false` 避开这一问题，重复构建保留旧的带哈希静态资源，新的 `dist/index.html` 始终引用当前构建。它不影响账户或数据库；运行数据不在 `dist` 内。正式分发时应使用全新目录构建，避免积累旧资源。请保留锁文件，用 `npm ci` 安装一致的依赖。

## 游戏版界面与操作

界面采用 **Three.js + WebGL 2** 的原创低多边形 3D 小镇：斜俯视正交相机、立体木屋与屋顶、树木、河流、小桥、光照阴影、人物行走与六色装扮。点击通过 3D 射线拾取定位建筑或地面，再沿共享地图规则寻路；不是把二维地图贴到一个平面上。业务表单保留 React／HTML，避免把阅读与输入变成难以使用的 3D 控件。

借鉴田园生活游戏的空间互动方式，**不使用《星露谷物语》的贴图、角色、音乐、地图或商标素材**。

### 图形兼容与性能

- 当前使用 Three.js 的 WebGLRenderer，**没有启用 WebGPU**；成员无需开启 WebGPU 实验选项。浏览器需要支持 WebGL 2，并允许创建图形上下文。
- 静态场景按几何体／材质合批为 InstancedMesh，共享人物几何体与材质；像素比上限 1.5，动画渲染上限约 30 帧／秒，不是对所有设备的帧率承诺。
- 手机使用更近的跟随视角；切到后台停止绘制，减少动效偏好下关闭行走摆动和水纹动画。
- 窗口尺寸变化时更新正交相机与画布，卸载时释放几何体、纹理、材质、实例和图形上下文。
- 若 WebGL 不可用，明确提示而不是留下无说明的空白；底部工具栏仍能使用共读、账簿、集市和邀请。图形上下文意外丢失时保留业务页面，浏览器恢复上下文后继续绘制。
- Three.js 增加了前端下载体积，Vite 构建目前会提示单块超过 500 kB；没有通过调高阈值隐藏提示。尚未做低端真机性能或大人数场景压测。

地图地点与真实功能对应：

- **云间书屋**：领读、讨论、私有笔记、共同成果与语音。
- **愿力公告板**：贡献悬赏、领取任务、提交与验收。
- **善友集市**：服务上架、购买托管、交付、结算和争议。
- **功德账房**：余额、流水、贡献履历、导出和对账。
- **迎新小屋**：成员、定向邀请、身份确认与书目安排。
- **回响之树**：自己的笔记及庭院共同成果。

已登录且连接实时通道的成员会显示在地图中；移动与主动表情通过服务端 SSE 同步。服务端检查通行格、单步距离和基本频率，不会因走路、换装或表情增发功德币。**位置和表情仅在当前在线期间保留，断线离场后清除，服务器重启后重新出生。** 衣服偏好保存在当前浏览器，进入庭院后移动或重新选择装扮可同步给其他成员。

右上角显示本地实际日期和时间；「晴」是庭院固定的虚拟天气，不是本地天气预报。没有疲劳值、强制签到、饥饿或在线时长奖励，不把共读变成打卡任务。

## 2. 第一场怎么用

1. 管理员建立庭院后，进入「善友与邀请」。
2. 输入一位**直接认识的成年伙伴**的邮箱，确认后生成定向邀请。
3. 通过可信私聊发送链接。系统不会代发邮件；链接绑定邮箱、单次领取、默认 7 天有效，可以撤销。
4. 伙伴打开链接，自行设置账户并确认成年和公约，先成为「试住伙伴」。
5. 管理员确认常住，首次从公共愿力池拨付 20 GC。暂停后恢复不会再次发放。
6. 在「共读室」选择相聚、静读、共议、回照等阶段，领读人选择段落并点击「带大家读这一段」。
7. 其他人可以勾选跟随，也可以独立选择段落。可以举手、写私有笔记或主动分享理解卡片。
8. 领读人整理并发布共同成果。主要理解、未决分歧和下次问题都会保留。
9. 更换书目或领读人时，管理员在「善友与邀请」开始新场次。旧场次结束，已发布成果、原文和个人笔记保留。

**默认书目是项目原创的《共读，从相聚开始》14 段演示文本，不冒充经典。** 管理员可导入有权使用的正式文本。用空行分成 2—200 段，最多 60,000 字符；书目不会自动从私人知识库读取。

## 4. 功德币的首版规则

以下数字是可调整的试点参数，不代表任何传统经典的统一货币规则。

- 固定创世发行 **1,000 GC**，初始进入公共愿力池。
- 管理员首次获得 20 GC；其他伙伴首次确认常住获得 20 GC，均从公共池划拨。
- 不因签到、挂机、发言数量、邀请人数或互赞发币。
- 悬赏发布时锁定公共预算，验收后进入交付者账户，并生成独立贡献履历。
- 服务购买时锁定买方余额，确认交付后给提供者。首版无手续费、无销毁。
- 未交付前，任一当事人可取消，托管款全部退给买方。
- 已交付的争议先冻结；非当事管理员可以退款或结算。
- 管理员自己是当事人时，不能自裁；双方可分别表达退款／结算意愿，**只有两人选择一致才实际执行**。不能达成一致则保留托管，线下继续协商，不自动没收。
- 未提交的领取任务可以归还；已提交的任务先由管理员验收或要求补充。
- 余额不决定身份、领读资格或解释权；花币不抹去贡献履历。
- 不连接区块链，不充值，不提现，不兑换现金，不承诺升值，不做推荐返佣。
- 首版不提供自由转账或借贷。币通过验收、购买、退款和自愿支持公共池流动。

采用平衡分录、后端事务、非负余额与幂等编号，管理员可以在「功德账簿」执行对账。发行对方账户是专用会计账户，负数不代表任何成员债务。

## 5. 隐私与安全边界

- 私人笔记默认只有作者通过应用 API 读取；管理员普通页面也不能读取。
- 主动分享的卡片向本庭院有效成员开放；作者可以撤回分享。
- **服务器／数据库维护人员仍具有底层访问能力**。首版不是端到端加密，不应存放高度敏感信息。
- 密码使用随机盐与 scrypt 哈希；会话与邀请仅存 token 哈希。
- 登录使用 HttpOnly、SameSite Cookie；修改操作校验 Origin，默认不开放跨域 API。
- 登录和注册入口有单实例、按来源地址的基础限流；没有完整的分布式风控。
- 实时 SSE 广播状态失效提示、在线角色的坐标／外观／主动表情，以及经授权的定向语音信令；不广播私人笔记正文。位置与表情仅属于庭院内的角色，不是现实定位或推断出的情绪。
- 成员暂停后撤销登录会话，断开实时连接。余额、贡献和笔记保留，不自动没收。
- 成年是成员声明和管理员的人际确认，**不是平台完成了证件核验**。
- 邮箱用于定向匹配，**没有接入邮件验证码，不能证明邮箱所有权**。请通过可信私聊发邀请并线下确认身份。
- 没有外部字体、统计埋点或自动模型调用，不会上传整个 Obsidian 知识库。
- 首版没有自助找回密码、多人管理员授权、细分治理投票、复杂审计后台或自动备份计划。管理员密码请用密码管理器保存。

## 6. 数据与备份

默认数据位于：

```text
.local-data/reading.sqlite
.local-data/reading.sqlite-wal
.local-data/reading.sqlite-shm
```

这些内容、`.env`、依赖和测试截图都已加入忽略规则，不应公开提交。

**最简单的可靠备份方式：**

1. 正常停止服务，等待进程退出，避免其他实例仍在使用数据库。
2. 把整个 `.local-data` 目录复制到受控备份位置，不要只复制运行中的主 SQLite 文件。
3. 恢复时先停止服务，再把备份目录放回原处。
4. 先在独立目录和端口试恢复，核验账户、成果和账本后，再用于正式运行。

运行中备份需要 SQLite 官方备份机制；不要把热复制单个 `.sqlite` 文件当作一致备份。

通过 `DATA_DIR` 可以把运行数据放到知识库和 Git 之外的私有目录。不要同步或公开分享活跃数据库。个人导出不是全站备份，无法替代邀请、权限与账本等运行状态。

## 7. 内部成员远程使用

当前默认地址仅限这台电脑。**邀请制属于访问控制，不等于已经建立了成员之间的网络连接。** 把 `127.0.0.1` 链接发给别人，别人访问的是他们自己的电脑。

正式远程试用前，另行准备：

- 经你授权的内网／服务器入口和可访问域名。
- HTTPS 反向代理，代理保留正确的 Host，关闭 SSE 缓冲。
- `PUBLIC_ORIGIN=https://你的实际域名`，无尾斜线和路径。
- `COOKIE_SECURE=true`；配置公网入口时程序会要求 HTTPS 和安全 Cookie。
- 私有持久存储、备份恢复、管理员密码与邀请发送规范。
- 只对代理开放后端端口，不直接暴露开发服务器或数据库目录。
- 代理层请求限流；首版不信任任意 `X-Forwarded-For`，代理后基础限流会共享代理地址。

环境变量示例仅作说明：

```dotenv
HOST=127.0.0.1
PORT=4317
PUBLIC_ORIGIN=https://reading.example.org
COOKIE_SECURE=true
DATA_DIR=/private/cloud-reading-data
```

这里没有自动创建服务器、配置域名或公网发布；这些需要单独授权和实测。

### 语音的额外条件

- 本机 localhost 可以申请麦克风；普通局域网 HTTP 地址通常不具备安全上下文，无法使用麦克风。
- 默认不连接任何外部 STUN／TURN。本机直连可测试，跨网络或不同 NAT 下不能保证接通。
- 需要跨网时，可配置 `RTC_ICE_SERVERS` 为 WebRTC ICE 数组，使用你授权的服务。TURN 凭据会提供给登录成员，应采用短期凭据；不要配置高权限长期秘密。
- WebRTC 直连可能向通话伙伴暴露网络地址。服务端不录音，但无法阻止对方在自己的设备上录制。
- 首版最多 6 人同时语音，适合小组试点；更多成员应改为 SFU 架构，不应无限扩大 mesh。
- 自动化测试中的合成音源只验证媒体连接与权限流程，不能代替真人听感、回声、丢包或跨网验收。

## 8. 测试

```bash
npm run check
npm run test:e2e
```

- `check`：TypeScript、生产构建、19 项 Node 后端测试。
- `test:e2e`：启动临时数据库的独立服务，使用 Windows 本机 Microsoft Edge，验证业务闭环、双人语音、3D 庭院射线交互、图形上下文恢复、无 WebGL 降级共 5 项完整场景；不会写入 `.local-data` 或创建默认运行账号。
- 浏览器测试使用 4321 端口，不复用已有服务；需要端口空闲且已安装 Edge。
- 其他系统可以把 `playwright.config.ts` 的 `channel` 改为可用浏览器，或安装 Playwright Chromium 后移除 `channel`。
- 浏览器截图输出到 `screenshots/`，失败记录在 `test-results/`；全部不提交。请不要把真实成员数据的截图公开发送。
- Node 24 的 `node:sqlite` 可能显示 `ExperimentalWarning`；这是运行时状态说明，不是测试失败。升级 Node 时应重跑测试和恢复演练。
